# Integrate Learning

把用户已经理解并亲自记录的材料纳入正式知识网络。输入笔记不是“知识来源”；它是整合输入。视频、课程、书籍、实践或个人推断才是可选的来源信息。

## 1. 接收并约束输入

要求用户给出 Vault 相对路径，例如：

```text
/skill:integrate-learning 00-原始笔记/高速PCB.md
/skill:integrate-learning 00-原始笔记/STM32/
```

执行前必须：

1. 解析 Vault 根目录和用户给出的路径。
2. 拒绝绝对路径、包含 `..` 的路径、符号链接跳转以及不在 `00-原始笔记/` 下的目标。
3. 单文件目标必须是 `.md`；目录目标递归收集 `.md` 文件。
4. 按 Vault 相对路径排序，并在开始时冻结为“输入清单”。之后新出现的文件不自动加入本批次。
5. 非 Markdown 文件完全忽略：不读取、不计入覆盖率、不移动、不删除。

目标不存在、没有 Markdown 文件或安全边界无法确认时停止并说明原因。不要退化为扫描整个 `00-原始笔记/`。

## 2. 切分内容单元

逐篇读取冻结清单，将内容切分为有独立去向的语义单元，例如：

- 一个边界清楚的概念或因果命题；
- 一套方法、流程、规则或检查项；
- 一个需要连接到 Topic Map 的主题入口；
- 输入中明确写出的来源信息；
- 用户的例子、推导、观察、疑问或尚不可靠的判断。

切分是为了追踪去向，不是为了机械地“一段生成一篇笔记”。保留原意、适用条件、反例与用户尚未解决的不确定性；不得替用户补造事实、来源或理解证据。

## 3. 检索正式知识并决定去向

制定去向前读取并遵循 [领域标签注册表](../../docs/domain-tags.md)。为每个准备新建或更新的正式知识文件选择一个主领域；只有真正跨领域时才增加第二个标签。细粒度主题保留在 `topics`、Topic Map 或正文链接中。

只检索正式知识目录与必要的本地状态，不把默认隔离目录当作搜索语料：

- `01-学习问题/`
- `02-概念/`
- `03-主题地图/`
- `04-来源/`
- `05-实践与产出/`
- 必要时 `90-学习会话/`、`99-归档/` 和 `.learning/`

为每个内容单元选择恰当去向：

- 概念、机制、边界清楚的命题：新建或更新 `02-概念/`。
- 主题入口与多笔记导航：新建或更新 `03-主题地图/`。
- 方法、流程、检查清单、设计步骤或实践总结：新建或更新 `05-实践与产出/`。
- 只有输入明确包含标题、作者、链接、课程或出版信息等出处时，才新建或更新 `04-来源/`。
- 暂时不宜正式化但值得保存的内容：明确保留到某个精确位置。
- 重复、明显错误或没有长期价值的内容：只能在计划中说明理由并由用户接受后标记为“明确丢弃”。

先查重再决定新建。不要用同义标题制造重复 Concept Note；也不要把“高速 PCB”“STM32”这类宽主题整体塞进单篇概念笔记。

## 4. 提交一次批次整合计划

写入前向用户展示一份可核查的完整计划，至少包含：

- 冻结的输入清单；
- 准备新建的文件及其核心命题或用途；
- 准备更新的文件及差异摘要；
- 每个新建或更新文件拟使用的领域标签；
- 保持不变的相关文件及理由；
- 每个内容单元的预定状态与去向；
- 明确丢弃项及理由；
- 无法处理或需要用户决定的项。

如果内容不适合注册表中的任何领域，在计划中提议新的宽泛标签，说明边界和理由，并把注册表变更纳入同一次批次确认。不得使用 `domain/other`，也不得按单个技术或笔记临时造窄标签。

最后只请求一次批次确认。用户回复“可以”“继续”“按这个做”等普通肯定答复，即授权计划中列出的全部非破坏性创建和更新，不再逐文件追问。

用户没有确认前不写正式知识。实际执行需要新增、改名、覆盖或改变计划中的目标时，先暂停并展示偏差，获得新的批次确认。

## 5. 精确写入

严格按已批准计划执行：

- 更新前重新读取目标，防止覆盖用户在确认后作出的修改。
- 保留现有 YAML、标题、链接、无关标签和有价值内容；更新项不得整篇静默重写。
- YAML 的 `tags` 使用列表格式；每个正式知识文件包含一个主领域标签，真正跨领域时最多两个。
- Concept Note 写明唯一核心命题，并链接必要的前置、解释、对比或应用。
- Topic Map 负责导航，不复制各 Concept Note 的正文。
- 方法和检查清单保留顺序、判断条件、失败模式与实际约束。
- 来源记录只写输入中实际存在的溯源信息；缺少信息时标记缺失，不猜测。

## 6. 回读验证与覆盖报告

写完后重新读取所有新建或更新的目标，验证：

- 文件存在且内容可解析；
- 标题、核心命题和目标目录符合计划；
- 领域标签存在、属于已确认的注册表且数量不超过两个；
- 新增的内部链接能够解析，或被明确标记为待建链接；
- 没有覆盖计划外的内容；
- 每篇输入笔记及每个内容单元恰好具有一个最终状态。

覆盖报告的状态只能是：

- `已整合 → <目标文件>`
- `已保留 → <精确位置>`
- `明确丢弃 → <用户已接受的理由>`
- `未处理 → <原因>`

按“已有最终状态的内容单元数 / 总内容单元数”计算覆盖率。只有没有任何 `未处理` 且覆盖率为 100% 时，整合才完成。验证失败或存在未处理项时，保留输入原位并报告下一步，不得进入清理。

## 7. 可恢复地清理输入

达到 100% 覆盖后，展示将移动的精确 Markdown 输入清单，并询问是否移入 `.trash/`。普通肯定答复即可授权这次可恢复移动。

移动规则：

1. 只移动冻结清单里的 Markdown 文件。
2. 保留 `00-原始笔记/` 下的相对路径。例如 `00-原始笔记/STM32/定时器/PWM.md` 移到 `.trash/00-原始笔记/STM32/定时器/PWM.md`。
3. 目标已存在时不覆盖，停止该批次清理并报告冲突。
4. 移动后只清理本批次路径中已经为空的目录；始终保留 `00-原始笔记/` 根目录。
5. 非 Markdown 文件会使目录保持非空，绝不随目录删除。
6. 清理后再次核对原路径、回收路径和输入清单，并报告结果。

本 Skill 永不永久删除输入，也不自动清空 `.trash/`。永久清空只能由 `/skill:purge-trash` 或用户明确的清空命令触发。
