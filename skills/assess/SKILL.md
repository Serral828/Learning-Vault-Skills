# Assess

评估的目标是获得有区分度的能力证据，而不是迫使用户复述刚讲过的内容。

## 评估前

1. 明确要验证的可观察能力以及通过后会改变的决定，例如继续教学、进入下一节点或晋升笔记。
2. 读取当前对话、`.learning/learner-profile.json` 和已有掌握证据。用户已经展示过的能力直接计入，不重复考察。
3. 估计用户当前边界，在边界稍外侧出题。若用户已掌握基本方法，转向约束冲突、失败归因、边界条件或实验设计。
4. 如果没有一个问题会改变判断，就不要为了流程而提问。

## 问题准入门槛

提出前确认问题同时满足：

- **目标相关**：答案直接证明目标能力，而不是外围记忆。
- **不可复述过关**：仅把上一段换一种说法不能得到满分。
- **包含新情境**：加入真实案例、数据、约束、异常、反例或取舍。
- **有可观察标准**：能从回答中判断推理、适用条件或行动方案是否成立。
- **难度匹配**：不是用户已经明确展示过的常识，也不依赖尚未教授的隐藏前置。

任一项不满足就重写或取消问题。

## 优先任务类型

根据能力目标选择一种最合适的形式，不为凑数量全部使用：

- **预测**：条件改变后会发生什么，为什么。
- **诊断**：从日志、现象或结果定位最可能的失败机制。
- **权衡**：指标冲突时作出决定并说明红线。
- **设计**：设计实验、控制策略、评估方案或实现步骤。
- **迁移**：把概念应用到表面不同但结构相似的新问题。
- **反例与边界**：找出方案失效的条件并提出修正。

优先使用用户正在做的项目和真实目标作为背景。无法取得真实材料时，构造最小但完整的工程情境。

## 交互与语气

- 使用共同解决问题的专业语气，不扮演审讯者或故意装傻。
- 禁止使用“凭什么”“你怎么证明”“这不是显然吗”“连这个都”等贬低或挑衅表达。
- 不问答案显然包含在问题里的反问，不用“为什么需要指标”之类常识题拖延进度。
- 一次给足做判断所需的信息，然后只问一个核心任务。
- 回答充分时立即停止，不通过不断追加“那又怎样”制造虚假深度。

## 评价回答

先判断证据，再决定是否追问：

- `0 无证据`：没有作答，或内容与目标无关。
- `1 识别`：能复述或识别概念，但不能独立用于情境。
- `2 应用`：能在给定情境中正确运用，并说明关键理由。
- `3 迁移`：能处理新约束、边界或指标冲突，主动检查失败模式。

反馈时：

1. 先指出回答已经证明的能力。
2. 再指出影响结论的具体缺口；不要评价人格或笼统说“理解不够”。
3. 达到目标要求就结束评估。通常 `2` 可继续学习，`3` 是较强晋升证据；具体门槛服从 Learning Quest。
4. 未达到时先教授一个缺口，再换一个等价的新情境补测。同一目标最多补测一次；再次失败就返回 `teach`，不继续纠缠。

## 示例质量

低质量：询问“有了 eval set 和指标后你会怎么判断 Prompt 变好还是变坏”。这只诱导复述方法名。

合格：给出 Prompt A/B 在常规任务、边界安全、成本上的冲突数据，要求决定是否发布，并说明指标优先级、红线和下一项实验。该任务能够区分会背术语与会做评估决策。

## 输出证据

评估结束后简要记录：目标能力、任务情境、证据等级、已证明内容、剩余缺口和下一步。只有需要持久化时才提议写入 Session Log 或掌握状态，未经用户确认不修改正式笔记。
