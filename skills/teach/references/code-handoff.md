# 可运行代码的执行交接

只要准备给出需要用户复制到本地运行、查阅或修改的代码块，就不要把复制粘贴当作默认交付方式。改为创建完整的练习工作区并打开编辑器。

### 读取配置

先读取 `.learning/tooling.json`：

- `learningLabsRoot`：Vault 内默认隔离的代码实验根目录，通常是 `98-代码实验/`。
- `editor.command`：用于打开工作区的编辑器命令。
- `handoff.openAfterWrite`：写入成功后是否打开编辑器。
- `handoff.runAfterWrite`：必须保持为 `false`，除非用户在当前请求中明确要求运行。

配置不存在或目标目录不明确时只询问一次，不猜测路径。不要把个人绝对路径写入可复用 Skill。

`98-代码实验/` 不参与普通检索，但本 Skill 在已经确定具体实验目录后可以显式访问该目录。不要扫描其他实验来寻找“可能相关”的代码；只有用户明确要求继续某个既有实验时才读取对应目录。

### 创建练习工作区

1. 根据当前知识点或实验目的生成简短、稳定的 kebab-case 目录名。
2. 同一实验继续迭代时复用原目录；若名称冲突但内容属于另一实验，使用有意义的后缀。未经确认不得覆盖已有文件。
3. 创建能够直接查阅和运行的完整材料，而不是强制挖空核心代码。学习目标是方法、行为或取舍时，代码可以是完整实现。
4. 至少写入：
   - 可运行的源代码文件；
   - `README.md`，说明学习目标、方法思路、文件作用、前置条件、运行命令、关键参数、建议观察点和可尝试的修改；
   - 项目实际需要的依赖声明；
   - 涉及环境变量时创建 `.env.example` 和 `.gitignore`，只写变量名和占位符，绝不写入真实密钥。
5. 代码和说明全部写入成功后，执行配置中的编辑器命令打开整个实验目录，例如 `code <lab-directory>`。
6. 只完成“写入并打开”。不要自动安装依赖、启动服务或运行代码；这些动作由用户决定。

完成后在聊天中只说明实验路径、文件清单、建议从哪里开始以及运行命令。除非用户要求，不再重复粘贴已经写入文件的完整代码。

### 能力与权限边界

执行交接需要 Agent 具备目标目录写入与运行编辑器命令的权限。当前模式缺少权限时，明确说明需要切换到允许文件写入与 Shell 的模式；不要悄悄退化成长代码块让用户复制。
