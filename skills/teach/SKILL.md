# Teach

目标是改变用户可验证的知识状态，而不是生成一篇教程。

## 1. 建立 Learning Quest

- 将用户目标改写为一个真实问题或可观察能力。
- 明确完成标准：用户最终应该能够解释、判断、推导或完成什么。
- 检查 `01-学习问题/` 是否已有相关 Quest；不要重复创建。
- 未经用户确认，不写入文件。

## 2. Probe 当前理解

- 一次只问一个问题并等待回答。
- 从宽到窄探测前置知识、已有理解、误解和不确定性。
- 允许用户回答“不知道”。不要用暗示让用户猜中。
- 不只使用选择题；混合自由回忆、解释、预测和最小应用题。
- 将“听起来熟悉”与“能够独立解释或应用”区分开。

## 3. 生成暂时性知识路径

- 根据目标和 Probe 结果生成最小依赖图，不展开整套学科。
- 使用 Mermaid DAG 展示当前理解、必要前置、下一节点和目标能力。
- 对每个节点说明为什么现在需要它。
- 让用户确认或修正路径后再教学。

## 4. 一次教一个节点

- 每轮只推进一个可消化的推理步骤。
- 从用户已有理解出发，避免重复已经掌握的内容。
- 必要时使用公式、例子、反例、图示或小实验。
- 关键事实在教授前调用 `verify`；无法核实时明确标记不确定性。
- 不要因为用户说“懂了”就直接进入下一节点。

## 5. Lock-in

至少使用两种证据确认理解：

1. 用户不看答案，用自己的语言解释。
2. 用户在新例子、推导、判断或实践中应用。

若失败，识别错误类型：缺少前置、概念混淆、公式机械记忆、例子不足或表述问题。调整解释或插入前置节点，不要只是重复原话。

## 6. 收束会话

- 总结本次知识状态变化，而不是总结全部聊天。
- 列出仍未解决的问题和下一节点。
- 只有通过 Lock-in 的内容才能调用 `distill` 提议晋升 Concept Note。
- 把错误和验证证据记录到 Session Log；不要把原始会话当成正式知识。
