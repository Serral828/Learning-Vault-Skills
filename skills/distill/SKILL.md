# Distill

## 晋升门槛

正式 Concept Note 必须同时满足：

- 当前 Learning Quest 的全部必需节点已经分别完成一次节点评估，状态可以是 `validated` 或 `assessed_with_gaps`。
- 用户已经完成覆盖这些节点的实际应用输出，且一次综合评估已经结束，状态可以是 `passed` 或 `completed_with_gaps`。
- 用户自己的解释和新情境应用作为掌握证据记录；它们影响 mastery 状态，但不是生成一篇准确知识笔记的补测门槛。
- 关键事实有来源或被明确标注为个人推断。
- 笔记边界足够小，并有一个唯一核心命题。

如果教学流程尚未完成首次节点评估、实际应用输出或首次综合评估，保留在 `90-学习会话/`。评估已完成但存在缺口时可以继续 Distill，同时把缺口留在掌握状态中。

用户审阅或确认一篇流畅草稿，只能授权修改或写入，不能替代首次节点评估、实际应用输出或首次综合评估。这里要求的是每个阶段执行一次，不要求失败后补测或复评。

## 编排触发

- `teach` 只有在全部节点各评估一次、实际应用输出和一次综合评估依次完成后，才在收束审计中主动调用本 Skill；用户不需要再发一次 `/skill:distill`。
- 接收到综合评估 `passed` 或 `completed_with_gaps` 且 `distillReady: true` 的结果后，直接进入查重和草稿流程；不要再问用户“先补测还是先起草”。
- 即使某个节点的局部证据已经很强，也不能在 Quest 综合评估前提前整理。综合评估用于区分可写入的准确知识与仍需保存在 mastery 状态中的个人掌握缺口。
- 展示完整草稿并请求确认是 Distill 提案本身，不等于未经授权写文件。用户确认后才落盘。
- 用户明确没时间查看草稿时，将该节点交给 `learning-hub` 保存为待执行 `distill` 动作；下次恢复先展示草稿，不重新教授或补测已经评估的节点。
- 用户明确拒绝本次晋升时记录为 `declined`，不要在同一证据不变时反复推销；以后由用户主动要求或新增证据后再提议。

## 提炼流程

1. 搜索 `02-概念/`，避免创建重复或近义笔记。
2. 选择清晰的名词短语标题；Topic Map 才使用宽泛主题名。
3. 保留用户表达中准确、有辨识度的理解，将其自然融入定义、直觉或机制解释；不要把对话原话单独堆成“我的理解”。
4. 读取并遵循 [领域标签注册表](../../docs/domain-tags.md)，选择一个主领域；只有真正跨领域时才增加第二个标签。
5. 读取并遵循 [正式笔记的实例与链接规范](../../docs/concept-note-writing.md)，为当前概念选择与领域真实工作方式匹配的应用案例，并检索可建立语义关系的现有笔记。
6. 读取并遵循 [Topic Map 创建与归属规范](../../docs/topic-map-writing.md)，为当前概念选择至少一个最直接的上位主题地图并搜索 `03-主题地图/`。地图存在时准备更新；不存在时必须准备一份最小地图草稿，不能检查后不了了之。
7. 以 [Concept Note 模板](assets/concept-note-template.md) 生成草稿，并删除所有说明性占位符。除非用户明确指定其他模板，不沿用旧模板中的“我的理解”“形式与例子”“理解验证”“来源与证据”等固定章节。
8. 在“概念与机制”的相应位置嵌入至少一个领域匹配的实际应用案例，包含具体场景、目标、条件、实施材料、可观察结果、概念映射和条件变化。软件知识按需使用实际代码、查询、配置或日志；硬件知识使用具体器件参数、连接或布局约束、测量与故障诊断；其他领域使用相应的演算、实验、决策、文本或设计案例。案例后必须抽象回一般机制，不能形成与正文割裂的附录。
9. “关系”中的每个目标都使用实际 Obsidian Wikilink，并写明关系类型和理由；模板里的纯文本槽位不能原样保留。新 Concept Note 必须链接所选主 Topic Map，Topic Map 也必须链接该 Concept Note。不得制造无依据链接。
10. 在同一次确认中分项展示 Concept Note 的目标路径、领域标签和完整草稿，以及 Topic Map 的目标路径和完整新建草稿或更新差异。若需要新增宽泛领域标签，把注册表变更也并入这次确认。
11. 用户可以分别确认 Concept Note 和 Topic Map。确认后才写入对应文件并更新掌握状态；Topic Map 变更被推迟时，把具体地图目标和待执行操作交给 `learning-hub` 保存，不能因 Concept Note 已写入而丢失。

## Topic Map 收尾门槛

每篇新晋升的 Concept Note 都必须完成一次地图路由：

- 对 KNN 这类小知识点，选择“机器学习”这类可持续扩展的上位知识面，而不是创建“KNN Topic Map”。
- 若合适地图已经存在，Distill 提议更新它；若不存在，Distill 必须提议创建它。
- “未找到 Topic Map”是创建提案的触发条件，不是允许结束的条件。
- 新建或更新的 Topic Map 统一只使用 YAML 标签 `map`，不添加 `domain/...`。
- 用户明确拒绝地图变更时可以结束本次地图提案；用户只是没时间时必须保存为待完成动作。

不得直接覆盖已有 Concept Note。需要修改时先展示差异和理由，保留现有无关标签；增加、移除或替换领域标签必须出现在差异中。

`理解验证`、用户作答和晋升证据写入掌握状态或 Session Log，不进入 Concept Note。只有存在值得未来追溯的外部资料、标准、数据或实验记录时才增加“参考”，不为满足格式创建空章节，也不把本次对话当成来源。

展示草稿前自检：正文是否先完成基本阐述；案例是否嵌入并推动机制解释；是否使用该领域真实的应用材料；是否包含具体约束、过程、结果和条件变化；是否把构造案例冒充真实事件；关系目标是否写成可解析的 `[[...]]`；每条关系是否有语义理由；是否已经为新概念选择上位 Topic Map；地图不存在时是否展示了创建草稿；Concept Note 与地图是否双向链接；地图标签是否只有 `map`。
