# 原始笔记的封闭语料转换边界

`integrate-learning` 是忠实转换流程，不是教学扩写、百科补全或研究流程。本批次输出的正式知识只能来自用户明确指定的原始笔记及其中合格的图片括号说明。Agent 可以重组、合并重复、调整措辞、拆分笔记和建立有输入依据的链接，但不能把原始笔记之外的新知识混入转换结果。

## 两条同时成立的原则

### 不遗漏

开始规划前，逐篇把输入拆成可追踪的原子知识点，包括：

- 定义、命题、因果或机制说明；
- 前提、适用条件、限制、例外和反例；
- 步骤、判断规则、参数、公式、数值和单位；
- 例子、实验、观察、工程现象和失败经验；
- 对比、关系、引用、来源信息；
- 用户的疑问、不确定判断、冲突和待核查内容；
- 每个图片—说明对表达的对象、结构、现象和结论。
- 每张表格的表头、行标识、列维度、语义顺序、空值状态、单元格内容以及单元格与行列的对应关系。

标题、寒暄和纯排版不必当作知识点；但语义表格不是纯排版，行列关系本身属于知识。不能因为某段难归类、重复、可能错误或不够完整就静默省略。重复内容可以合并到同一目标段落，但覆盖账本仍要分别指向该目标。可能错误的内容按“原始笔记观点 / 待核查”忠实保留，不擅自修正成另一个结论。

### 不扩写

转换结果允许：

- 在不改变含义的情况下改写句子、统一术语和消除重复；
- 按单一核心命题拆分或合并内容；
- 添加只承担结构作用的标题、过渡句和导航语；
- 依据输入中已经表达或直接蕴含的关系建立 Wikilink；
- 检索已有 Vault 内容以查重、确认目标文件、选择 Topic Map 和避免覆盖，但不能把检索到的正文知识反向补进本批次输出。
- 按 [原始笔记表格保真规范](raw-note-tables.md) 修复无歧义的 Markdown 表格格式；语义表格默认保持表格，拆分、合并、转置或改成其他结构时必须先展示完整映射并取得批次确认。

转换结果禁止：

- 补写原笔记没有的定义、机制、因果、例子、反例、代码、公式、参数、数值或应用场景；
- 为了满足模板完整度而让 Agent 自行生成案例、解释或结论；
- 把常识、模型记忆、网络搜索结果或已有笔记正文伪装成原始笔记内容；
- 仅因同领域、同标签或标题相似就写入新的知识关系；
- 用一句更宽泛的总结替代原文中的条件、边界、数值、例子或不确定性。
- 只保留表格单元格文字，却丢掉表头、行标识、列维度、空值状态或对应关系；不得把对比表、映射表、规格表、参数表或决策矩阵摊平成一坨正文后声称完整覆盖。

如果某篇 Concept Note 按正式规范仍缺必要内容，不能用新知识补齐。应把已有内容完整保留在原始笔记的精确位置，标记为“待补充后晋升”，并把缺失内容放到转换后的建议中；不得用扩写换取表面上的完整，也不得把材料不足的内容伪装成完整 Concept Note。

## 覆盖账本

每个原子知识点获得一个批次内 ID，并记录原始位置与唯一结果：

```text
RN-001 | 原文：文件与行号 | 已整合 → 02-概念/目标.md#章节
RN-002 | 原文：文件与行号 | 已合并 → RN-001 的目标段落
RN-003 | 原文：文件与行号 | 已保留 → 原文件#待核查
RN-004 | 原文：文件与行号 | 未处理 → 缺少图片说明
```

一个知识点只能有一个最终状态，但多个知识点可以合并到同一目标。表格除整体 Table ID 外，每个有知识含义的单元格还要记录行标识、列表头和目标单元格；不能脱离行列语境只登记文字。完成前进行双向核对：从输入逐项确认有去向，再从输出逐段确认能够追溯到输入。只有全部知识点和表格关系都有状态、没有无来源的实质性新增内容，覆盖率才是 100%。

“明确丢弃”只适用于确认不承载知识的噪声、排版残留或用户明确要求不要保留的内容，并且必须在计划中展示并获得用户同意。重复、错误、疑问、反例和不完整内容都不是自动丢弃理由。

## 转换完成后的独立建议

完成报告之后可以提供一个与正式转换严格分隔的“转换外建议”，分为：

- **建议**：改善笔记结构、验证方式或实践形式的建议。
- **延伸**：原笔记尚未覆盖但可能值得以后学习的相邻问题。
- **质疑与待核查**：原笔记内部冲突、证据不足、表述含混或可能错误之处。

这些内容默认只出现在聊天报告中，必须明确标注“未写入正式笔记、不计入本批次输入和覆盖率”。它们不能被自动写进 Concept Note、Topic Map、来源或实践笔记，也不能改变已经完成的忠实转换。用户选择其中一项后，才把它作为新的教学、核查或更新任务另行处理。
