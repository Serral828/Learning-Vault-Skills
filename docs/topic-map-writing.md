# Topic Map 创建与归属规范

Topic Map 是宽泛知识面的导航入口，不是领域标签的替代品，也不是把 Concept Note 正文复制一遍。新概念晋升时必须判断它应当进入哪个上位主题地图；找不到合适地图时，结果应是“提出创建地图”，而不是“没有地图，因此不处理”。

## 选择上位主题

选择能够长期容纳多个相邻概念、又比领域标签更具体的最近稳定主题：

- `KNN` → `机器学习`，而不是为 KNN 单独创建地图，也不是直接使用过于宽泛的 `人工智能` 代替所有层级。
- `TCP 拥塞控制` → `计算机网络`。
- `React 服务端渲染` → `Web 开发` 或已有的更合适 Web 主题地图。
- `运算放大器负反馈` → `模拟电路`。

优先依据当前概念、Learning Quest 路径和已有知识结构判断，不把 `domain/...` 标签机械转换成地图名称。一个概念可以进入多个真正有导航价值的地图，但每次晋升至少处理一个最直接的主地图。

## 缺失地图时的必做动作

搜索 `03-主题地图/` 后：

- 有合适地图：提出把新 Concept Note 加入该地图，并展示将新增的 Wikilink 和理由。
- 没有合适地图：必须提出创建一个最小可用 Topic Map，展示目标路径、范围、完整草稿和它与新 Concept Note 的双向 Wikilink。不得只报告“未找到”后结束。
- 存在多个合理候选：优先提出最直接的主地图并说明理由；只有选择会显著改变知识结构时才问一个简短问题。
- 用户可以单独拒绝或推迟地图变更；这不撤销已经确认的 Concept Note，但必须明确保存为未完成的地图动作，不能静默丢失。

## 最小结构

```markdown
---
type: map
tags:
  - map
---

# <宽泛主题>

## 范围

<一句话说明本地图包含什么，以及相邻但不包含什么。>

## 从这里开始

- [[新晋升的 Concept Note]] — <它为什么是这个主题中的入口或组成部分。>

## 相关主题地图

- [[实际存在的相邻 Topic Map]] — <关系和边界。>
```

没有真实目标时删除“相关主题地图”，不得制造尚不存在的 Wikilink。地图初次创建时只有一个 Concept Note 也可以；它是后续扩展的稳定入口，不需要用虚假占位链接把版面填满。

## 链接与标签

- Topic Map 的 YAML `tags` 只包含 `map`。
- 地图使用 `[[Concept Note]]` 收录概念，并附一句导航理由。
- 新 Concept Note 的“关系”中加入 `所属主题：[[03-主题地图/<地图名>|<地图名>]] — <理由>`。
- 新建或更新地图与 Concept Note 可以放进同一次确认，但必须分项展示文件路径和改动；用户确认前不写入。
