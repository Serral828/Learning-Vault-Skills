# Topic Map 创建与归属规范

Topic Map 是宽泛知识面的结构化导航入口，不是领域标签的替代品，也不是把 Concept Note 正文复制一遍。它不只负责收录链接，还要把已经出现的 Learning Quest、Concept Note 和实践产出按清晰的组织轴分类，并在分类内部形成可读顺序。新概念晋升时必须判断它应当进入哪个上位主题地图以及地图中的哪个语义分组；找不到合适地图时，结果应是“提出创建地图”，而不是“没有地图，因此不处理”。

## 选择上位主题

选择能够长期容纳多个相邻概念、又比领域标签更具体的**最近**稳定主题；地图可以是任意深度的子地图，见下文“地图层级”：

- `KNN` → `机器学习`，而不是为单个概念 KNN 单独创建地图，也不是直接使用过于宽泛的 `人工智能` 代替所有层级。
- `TCP 拥塞控制` → `计算机网络`。
- `React 服务端渲染` → `Web 开发` 或已有的更合适 Web 主题地图。
- `运算放大器负反馈` → `模拟电路`。

优先依据当前概念、Learning Quest 路径和已有知识结构判断，不把 `domain/...` 标签机械转换成地图名称。一个概念可以进入多个真正有导航价值的地图，但每次晋升至少处理一个最直接的主地图。

## 地图层级：父地图、子地图与同级地图

主题地图允许多层嵌套，层数不限，但每一层都必须有导航价值。例如 `电路基础` → `电容的作用` → `低通滤波器`（笔记）。

**何时建子地图**：满足任一条件即可提出。

- 输入或主题是集合型的（如“X 的作用/分类/应用”），并能列出至少三个**同类并列**条目，其中可以包含 `status: seed` 的笔记。同一构造的组成部分或前置知识不算并列条目，不能据此建子地图，见 [笔记粒度](concept-note-writing.md)；
- 父地图某个分组已积累四个以上条目，并且它们构成自成一体的子主题。

不足三个并列条目时，直接放进父地图的语义分组，不建子地图。

**放置规则**：

- 一个概念只列在离它**最近**的那张地图，不向各级祖先地图重复列出。Concept Note 的 `所属主题` 指向这张最近的地图。
- 父地图在相应语义分组里只收录子地图入口，标注“（子地图）”和一句范围说明，不再列出子地图内部的概念。
- 建子地图时，若父地图已直接列出属于其范围的概念，提议把它们移入子地图，并展示结构差异。
- 子地图必须有 `## 上级与同级`：至少一个上级；同级只链接同一父地图下**已经存在**的兄弟地图，不制造占位链接。
- 上下级和同级关系必须两侧同时写入并回读验证：建子地图要同时更新父地图入口和子地图上级；发现已有同级地图（如 `电感的作用`）时两侧互链。

**条目总是真实链接**：地图里的每个条目都指向一篇真实笔记，包括材料偏薄、`status: seed` 的笔记（见 [笔记粒度](concept-note-writing.md)「材料偏薄时」一节），不设无链接的占位条目。薄笔记正常收录，后续补充材料后原地更新即可。

## 缺失地图时的必做动作

搜索 `03-主题地图/` 后：

- 有合适地图：读取地图当前链接的全部真实条目及其目标笔记，判断新 Concept Note 属于哪个语义分组，并检查现有条目是否需要移动、改名或重排；展示新增链接和必要的结构调整，不能只在末尾追加一行。
- 没有合适地图：必须提出创建一个最小可用 Topic Map，展示目标路径、范围、完整草稿和它与新 Concept Note 的双向 Wikilink。不得只报告“未找到”后结束。
- 存在多个合理候选：优先提出最直接的主地图并说明理由；只有选择会显著改变知识结构时才问一个简短问题。
- 用户可以单独拒绝或推迟地图变更；这不撤销已经确认的 Concept Note，但必须明确保存为未完成的地图动作，不能静默丢失。

## 选择地图的组织轴

每张 Topic Map 选择一个最能帮助理解该主题的主组织轴，并在后续更新中保持一致。组织轴必须来自实际知识结构，而不是固定模板。常见选择包括：

- **语义角色**：基础表示、核心机制、模型与方法、评估与边界、应用实践。
- **系统层次**：物理层、驱动层、协议层、服务层、交互层。
- **工作阶段**：问题定义、输入准备、设计或训练、验证、部署与维护。
- **对象或问题类型**：分类、回归、生成、优化；供电、信号、通信、控制。
- **时间或因果链**：适用于历史、流程、实验和机制演化主题。

不要把“基础、进阶、其他”当作默认万能分类，也不要机械套用机器学习的分类标题。分类名应让读者只看目录就能理解这个主题由哪些部分构成。禁止使用“其他”“杂项”“未分类”长期收容无法判断的条目；无法归类通常意味着需要重新理解条目关系、调整组织轴或选择另一张地图。

## 分类与排布规则

每次新建或更新地图都要执行以下步骤：

1. 读取地图里现有的 Quest、Concept Note、实践与相邻地图链接，并读取目标笔记的标题、核心命题和关系；不能只根据链接旁的一句话分类。
2. 选择或确认一个主组织轴，为每个 Concept Note 指定一个最能解释其作用的主分组。一个概念原则上只在知识结构中列一次；跨组作用写进说明或由 Concept Note 双链表达，避免重复堆链接。
3. 组内按“前置与输入 → 核心机制 → 方法或实现 → 评估与边界 → 应用”的实际依赖顺序排列；不适合该顺序时使用该领域自然顺序并保持一致。
4. 新条目加入后重新审计全部现有条目。若新知识暴露出更合理的分类，允许重命名分组、移动旧条目或调整顺序，但必须在提案中展示结构差异，不能静默重排。
5. 每个条目保留一句导航说明，重点解释它在本分组中的角色以及与前后条目的关系，不把 Concept Note 的定义压缩复制一遍。
6. 删除空分组和占位标题。只有一个概念时仍放进一个有语义的分组；随着内容增长及时拆分。已有四个以上概念却仍只有一个笼统的“已晋升概念”列表时，必须重新评估组织轴，不能直接继续追加。

Learning Quest、Concept Note、实践产出和相关 Topic Map 承担不同导航角色，默认分区展示；每个分区内部也应在条目足够多时按问题类型、阶段或子领域继续分组。不要把不同类型的节点混成一个无层次清单。

## 最小结构

```markdown
---
type: map
tags:
  - map
---

# <宽泛主题>

## 范围

<一句话说明本地图包含什么，以及相邻但不包含什么。>

## 上级与同级

<仅子地图需要；根地图省略。只写真实存在的地图。>

- 上级：[[上级 Topic Map]] — <本地图是它的哪个子主题。>
- 同级：[[同级 Topic Map]] — <与本地图的对照或边界。>

## 知识结构

### <根据当前主题生成的语义分组，例如“数据与表示”>

- [[Concept Note A]] — <它在该分组中的角色，以及为什么应先于或关联下一个条目。>
- [[子 Topic Map]]（子地图）— <该子主题的范围，以及为什么单独成图。>

### <另一个真实存在且非空的语义分组，例如“模型与算法”>

- [[Concept Note B]] — <它与本组其他概念的区别、依赖或衔接。>

## 问题驱动入口

### <真实问题类型；只有一个问题时可省略三级标题>

- [[Learning Quest]] — <这个问题会调用地图中的哪些知识部分。>

## 实践与产出

- [[实际存在的实践或产出]] — <它综合或验证了哪些概念。>

## 相关主题地图

- [[实际存在的相邻 Topic Map]] — <关系和边界。>
```

没有真实目标时删除“问题驱动入口”“实践与产出”或“相关主题地图”，不得制造尚不存在的 Wikilink，也不得保留空的语义分组。地图初次创建时只有一个 Concept Note 也可以，但必须把它放进一个能说明角色的真实分组；后续扩展时重新审计并形成更完整的分类，不需要用虚假占位链接把版面填满。

机器学习地图已有“数据表示与特征向量”“K 近邻分类（KNN）”和“线性回归”时，不应继续写成：

```markdown
## 已晋升的概念

- [[数据表示与特征向量]]
- [[K 近邻分类（KNN）]]
- [[线性回归]]
```

应至少按当前知识的真实角色组织为：

```markdown
## 知识结构

### 数据与表示

- [[数据表示与特征向量]] — 先把样本变成共享特征空间中的坐标，后续模型才能计算距离或线性组合。

### 监督学习模型

- [[K 近邻分类（KNN）]] — 在特征空间中根据邻近样本完成分类，直接依赖前面的向量表示。
- [[线性回归]] — 对特征做加权线性组合以预测连续值，提供与分类任务不同的监督学习入口。
```

这只是机器学习地图在当前内容下的一种组织方式，不是所有 Topic Map 的固定章节。

## 链接与标签

- Topic Map 的 YAML `tags` 只包含 `map`。
- 地图使用 `[[Concept Note]]` 收录概念，必须放在有语义的分类下，并附一句说明其组内角色、依赖或衔接的导航理由。
- 新 Concept Note 的“关系”中加入 `所属主题：[[03-主题地图/<地图名>|<地图名>]] — <理由>`。
- 新建或更新地图与 Concept Note 可以放进同一次确认，但必须分项展示文件路径、新概念的目标分组、现有条目的移动或重排以及最终完整结构；用户确认前不写入。
