# 原始笔记表格保真规范

原始笔记中的表格不仅是排版。表头定义共同维度，行与列建立对象、属性、条件和结果之间的对应关系；这种结构本身属于知识内容。只保留单元格文字、把表格摊平成连续段落，不算忠实转换。

## 适用范围

本规范适用于：

- Markdown 管道表格；
- HTML `<table>`；
- 用表格表达的对比表、规格表、映射表、决策矩阵、条件—结果表、数据记录和检查矩阵；
- 单元格中包含链接、代码、公式、图片或换行的表格。

图片里的表格仍按图片—说明规范处理；Agent 不能根据图片像素自行还原单元格，除非用户已经在紧邻括号说明中完整提供了所需结构。

## 核心原则

### 表格结构也是知识

必须同时保留：

- 表格标题或上下文；
- 表头名称和层级；
- 行标识；
- 列顺序与行顺序中具有语义的部分；
- 每个非空单元格的内容；
- 明确为空、未知、不适用或待补充的单元格状态；
- 单元格与对应行、列的关系；
- 表格旁已经写明的条件、单位、注释和例外。

例如：

```markdown
| 处理器 | 主要任务 | 并行特点 |
| --- | --- | --- |
| CPU | 控制与调度 | 少量强核 |
| GPU | 重复计算 | 大量并行核 |
```

不能只转换成“CPU 负责控制，GPU 负责重复计算”。这种正文丢失了统一比较维度和行列对应关系。

### 语义表格默认继续使用表格

对比、映射、规格、参数、决策、条件—结果和数据型表格默认以 Obsidian 可解析的 Markdown 表格写入正式笔记。不得因为正文更容易生成，就把它改成连续段落或无层级列表。

纯粹借两列表格做页面布局、且行列关系不承载知识时，可以改成正文或列表，但必须在整合计划中说明判断依据和目标结构。

## 输入扫描与覆盖账本

每张表分配稳定的批次内 Table ID，例如 `TB-001`，并记录原文件与起止行。覆盖账本至少追踪：

```text
TB-001 | 表格整体 | 原文件:起止行 | 表头与行列结构 → 目标文件#章节
TB-001-R01-C02 | 行=<行标识> | 列=<列表头> | 原始内容 → 目标表格对应单元格
```

相同内容可以合并，但不能失去它原本属于哪一行、哪一列。空单元格不能被擅自填充；原文明确写“无”“未知”“不适用”和真正空白必须区分。

## 允许的结构调整

只有为了 Obsidian 可读性且不改变关系时才允许：

- 修复明确无歧义的 Markdown 对齐行、转义符和换行；
- 将单元格内换行规范为 `<br>`；
- 对单元格中的 `|` 做 Markdown 转义；
- 将过宽表格按有意义的列组拆成多个表，并在每个子表重复稳定的行标识；
- 将表格移到更贴近其解释机制的章节；
- 在原文已经支持的情况下统一表头措辞或单位格式。

以下操作必须在整合计划中展示“原结构 → 新结构”、理由和完整映射，并随批次计划取得用户确认：

- 拆表、合表或转置；
- 调整具有语义的行列顺序；
- 将语义表格转换为列表、卡片或正文；
- 将多个来源表格合并到一个正式表格。

转换后必须仍能从每个目标单元格追溯到原表位置。不能通过批准结构调整，授权 Agent 补写原表没有的值或结论。

## 表格损坏或含混时

以下情况不得猜测：

- Markdown 管道数量使单元格边界不明确；
- 表头与数据列数量无法对应；
- 合并单元格的含义不能从原文确定；
- 单位、行标识或空值含义不明确；
- HTML 表格结构不完整，无法可靠恢复。

Agent 应一次性列出表格 ID、文件、行号和问题，把该表标记为 `未处理 → 表格结构含混`，提醒用户修复或确认结构。其他独立内容可以继续分析，但不能把这张表计入 100% 覆盖，也不能进入依赖它的正式写入或输入清理。

## 整合计划必须展示

每张表至少列出：

- Table ID、原文件与行号；
- 表头和行标识摘要；
- `原样保留`、`格式修复`、`拆分`、`合并`、`转置` 或 `转为其他结构`；
- 目标文件、章节和最终 Markdown 表格预览；
- 拆分、合并或转换的理由；
- 原表到目标表的行列映射；
- 无法处理的单元格和原因。

默认原样保留语义结构时也要在计划中明确说明，不能只列目标文件。

## 写入后验证

回读正式笔记并逐表检查：

1. 表格能被 Markdown/Obsidian 正确解析；
2. 表头、行标识和具有语义的顺序完整；
3. 原表每个非空单元格都有唯一目标；
4. 空、未知、不适用和待补充状态没有被混淆；
5. 单元格的行列归属没有改变；
6. 表内链接、代码、公式、图片和单位仍可解析；
7. 拆表时每个子表都保留足够的行标识和上下文；
8. 没有把多个单元格压缩成无法还原对应关系的一段文字；
9. 输出没有出现原表之外的新值、比较结论或推导。

只要任一表格验证失败，该表保持 `未处理`，整批不能声称 100% 覆盖，也不能清理对应原始 Markdown。
