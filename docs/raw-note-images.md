# 原始笔记图片说明约定

`00-原始笔记/` 中的图片内容不依赖模型直接识图。每个图片嵌入的下一物理行必须提供一段由英文圆括号 `(...)` 或中文圆括号 `（...）` 完整包围的文字说明，Agent 只依据这段用户提供的说明理解图片并规划知识去向。

## 写法

以下写法有效：

```markdown
![[附件/KNN决策边界.png]]
（二维分类图：蓝点和红点代表两个类别；K=1 时边界曲折，K=15 时更平滑，用于说明较小的 K 更容易受噪声影响。）
```

```markdown
![电源纹波波形](附件/ripple.png)
(示波器 CH1 测量 3.3 V 电源输出；负载突变时出现约 180 mV 峰峰值纹波，用于判断当前去耦不足。)
```

装饰性图片也必须明确说明：

```markdown
![[课程封面.jpg]]
（装饰性封面，不承载知识内容。）
```

## 机械判定规则

- 图片包括 Markdown 图片 `![说明](路径)`、Obsidian 图片嵌入 `![[路径]]` 以及 HTML `<img ...>`；Obsidian 嵌入只在目标具有常见图片扩展名时按图片处理。
- 去掉行首和行尾空白后，图片的下一物理行必须以 `(` 开始并以 `)` 结束，或者以 `（` 开始并以 `）` 结束。中英文括号不能混配。
- 图片与说明之间不能有空行。连续多张图片时，每张图片后都必须先写自己的说明。
- 括号内不能为空；“见图”“如上”“示意图”等不能帮助理解内容的文字视为说明不足。
- 说明行只归属于紧邻它上方的那张图片，不再作为独立正文重复切分，但其中表达的知识参与语义分析和整合规划。

## 说明应包含什么

说明不要求逐像素描述，但应足以替代本次知识整合所需的视觉信息。根据图片类型尽量包含：

- 图片是什么：图表、电路图、流程图、公式、代码截图、波形、实物照片等。
- 关键对象：坐标轴、曲线、模块、器件、连接、标签、数值或异常位置。
- 重要关系或现象：谁影响谁、变化趋势、先后步骤、测量结果或对比差异。
- 图片在笔记中的作用：它支持什么结论、解释什么机制，或只是装饰。

如果说明中的信息不足以支撑准备生成的知识结论，Agent 必须把它当作“说明不足”，不能根据文件名、alt 文本、周围主题或常识补猜图片内容。

## Agent 的处理流程

1. 在拆分原始笔记前扫描本批次所有图片嵌入，建立“笔记路径、图片所在行、图片目标、说明所在行、说明状态”清单。
2. 说明有效时，把括号中的内容视为用户提供的整合输入，用它判断图片对应的概念、机制、例子、参数、证据、疑问或实践记录；不得声称已经直接观察或验证图片像素。
3. 缺少说明、说明为空、括号不匹配或说明不足时，一次性列出全部问题，包含笔记相对路径、图片行号、图片目标和缺失原因，并提醒用户补充。
4. 有问题的图片及依赖它的语义单元标记为 `未处理 → 缺少可用图片说明`。其他内容可以先分析，但不得提交声称 100% 覆盖的最终整合计划，不得晋升依赖该图片的正式知识，也不得进入输入清理。
5. 用户补充说明后重新扫描整批输入；不能只凭聊天中的临时解释假装源笔记已经符合约定，除非用户明确授权 Agent 把说明写回原始笔记。

图片说明属于用户对图片内容的陈述，不自动等于外部来源、实测证据或已经核验的事实。

## 正式笔记中的写入规则

图片及其紧邻括号说明是不可拆分的内容单元。只要正式笔记采用了某个图片—说明对所承载的知识，就必须把图片嵌入和说明一起写入正式笔记，保持“图片行 → 下一物理行括号说明”，中间不能插入空行、标题、列表项或其他正文。

```markdown
### K 值如何改变决策边界

![[附件/KNN决策边界.png]]
（二维分类图：K=1 时边界曲折，K=15 时更平滑，用于说明较小的 K 更容易受噪声影响。）

这个现象反映了……
```

- 不得只复制括号说明而丢掉图片，也不得只嵌入图片而省略说明。
- 图片—说明对要放在它实际解释的概念、机制、步骤或案例附近，不集中堆到文末“图片附件”区域。
- 说明可以为了正式笔记的可读性做最小措辞整理，但不得改变用户原意、增加图片中未说明的对象、数值或结论；整理后仍必须完整包在一对中文或英文括号中。
- 装饰性图片默认不晋升到正式笔记；如果用户或内容需要保留，仍必须连同“装饰性图片”说明一起出现。
- 同一张图片在一篇正式笔记中原则上只嵌入一次，放在最能解释其作用的位置；其他位置用正文或内部链接引用，不重复铺图。
- 写入前必须确认正式笔记使用的附件路径稳定且可以从 Vault 解析。路径不存在、移动后会失效或附件去向尚未确认时，该图片—说明单元保持未处理，不能只写说明来绕过附件问题。

整合计划必须展示图片将进入哪篇正式笔记、放在哪个章节、最终图片链接和最终括号说明。写入后回读验证图片与说明相邻、附件可解析，而且不存在“有图无说明”或“有说明无图”。

## 清理前检查

图片二进制文件仍不是独立的 Markdown 输入，不会被静默移动或删除。准备把原始 Markdown 移入 `.trash/` 前，Agent 必须确认其中的图片引用在移动后仍可解析；相对路径会失效或附件不存在时，停止清理并报告，不得留下断链或孤立附件。
